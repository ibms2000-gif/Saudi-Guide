# دليل السعودية (Saudi Guide)

دليل تصفح لمدن ومحافظات المملكة العربية السعودية: مطاعم ومقاهي، تسوق،
خدمات عامة، صحة، تعليم، سياحة وفنادق. يُبنى كموقع ثابت بالكامل من بيانات
حقيقية مجلوبة من OpenStreetMap، وينشر على Cloudflare Workers.

**لا يعرض الموقع أي بيانات أرصاد جوية أو توقعات طقس أو درجات حرارة.**
راجع [`/legal/weather-notice/`](#) على الموقع المنشور لسبب ذلك
(الأنظمة السعودية تُلزم بترخيص لنشر بيانات الأرصاد الجوية).

## البنية

- `data/regions.json`, `data/cities.json`, `data/categories.json` — بيانات
  ثابتة محرّرة يدويًا (المناطق، المدن، تصنيفات الفئات الرئيسية والفرعية).
- `data/places/*.json` — **غير موجودة في هذا الإصدار**؛ تُولَّد بتشغيل
  `npm run data` (أو عبر سير عمل `refresh-data.yml`) الذي يجلب من
  Overpass API ويكتب ملفًا واحدًا لكل مدينة.
- `scripts/fetch-places.mjs` — يجلب بيانات الأماكن من Overpass API.
- `scripts/build.mjs` — يبني موقعًا ثابتًا بالكامل (HTML بدون جافاسكربت
  لازم للعرض) في `dist/`.
- `src/lib/*.mjs` — منطق التصنيف، النماذج، القوالب، بوابة الجودة، خريطة
  الموقع.
- `src/styles/site.css`, `src/client/app.js` — تنسيق الموقع وتحسين بسيط
  تدريجي (فلترة داخل القوائم الطويلة) بدون أي اعتماديات خارجية.
- `worker/index.js` — عامل Cloudflare لا يجلب أي بيانات حيّة؛ وظيفته فقط
  إعادة توجيه الروابط القديمة وتقديم ملفات `dist/` الثابتة.
- `tests/` — اختبارات وحدة (`node --test`) للتصنيف، النماذج، والبناء
  الكامل مقابل بيانات تجريبية (fixtures)، بما يشمل التحقق من:
  - ظهور إسناد مصدر البيانات في كل صفحة تعرض أماكن.
  - غياب أي محتوى طقس/درجات حرارة حيّة من كل الصفحات عدا صفحة السياسة.
  - أن خريطة الموقع لا تضم إلا الصفحات التي اجتازت عتبة الحد الأدنى من
    البيانات (`minForPage` في `data/categories.json`).

**لا توجد أي اعتماديات خارجية (`package.json` → `dependencies: {}`)**؛
كل شيء مكتوب بجافاسكربت قياسي (Node.js ≥ 20) ليعمل في أي بيئة دون
`npm install`.

## التشغيل محليًا

```bash
npm run data     # يجلب بيانات حقيقية من Overpass API (يستغرق دقائق، يُستحسن محليًا أو في CI)
npm run build    # يبني dist/ من data/*.json المتوفرة لديك
npm run dev      # يبني ثم يشغّل خادم تطوير محلي على :8788
npm test         # اختبارات الوحدة والبناء
```

إن لم تُشغّل `npm run data` بعد، سيبني `npm run build` موقعًا سليمًا لكنه
بلا أماكن (0 نتيجة لكل مدينة)؛ تعتمد الصفحات القابلة للفهرسة على بوابة
الجودة (حد أدنى من العناصر لكل فئة/مدينة)، فلن تُضاف أي صفحة فئة فارغة
إلى `sitemap.xml`.

## بوابة الجودة ومضاعفة الصفحات

لتجنّب "المحتوى المبعثر الرقيق" (thin/scaled content)، لا تُنشأ صفحة
فئة لمدينة معيّنة إلا إذا بلغ عدد العناصر المصنّفة فيها `minForPage`
(راجع `data/categories.json`)، ولا تُنشأ صفحة فئة فرعية إلا بثلاثة عناصر
فأكثر. هذا يحدّ عدد الصفحات، لكنه يزيدها تلقائيًا كلما اتسعت تغطية
البيانات في OSM لمدينة ما. أنواع الصفحات المولَّدة:

- الرئيسية، المناطق (فهرس + صفحة لكل منطقة)، الأقسام (فهرس).
- صفحة مدينة لكل مدينة (أقسامها المتاحة).
- صفحة فئة لكل (مدينة × قسم) تجاوز العتبة.
- صفحة فئة فرعية لكل (مدينة × قسم × فئة فرعية) تجاوزت 3 عناصر.
- صفحة محور وطني لكل قسم (المدن التي بها بيانات في هذا القسم) وفئته
  الفرعية إن وُجدت مدن كافية.
- `/about/data-sources/`, `/legal/weather-notice/`.

## مصدر البيانات والترخيص

جميع بيانات الأماكن من [OpenStreetMap](https://www.openstreetmap.org/copyright)
عبر Overpass API، بموجب رخصة [ODbL](https://opendatacommons.org/licenses/odbl/).
راجع [`data/DATA_LICENSE.md`](data/DATA_LICENSE.md) للتفاصيل الكاملة.
يُعرض إسناد المصدر في تذييل كل صفحة، وفي كل صفحة تعرض قائمة أماكن، وفي
صفحة `/about/data-sources/` المخصصة.

**تنبيه:** عملية الجلب (`npm run data`) لم تُشغَّل داخل بيئة تطوير هذا
العمل لأن الوصول الخارجي إلى Overpass API كان محجوبًا هناك؛ شغّلها محليًا
أو عبر سير العمل `refresh-data.yml` قبل أول نشر للحصول على بيانات حقيقية،
وراجع `dist/_build-report.json` بعد البناء لمعرفة عدد العناصر لكل قسم.

## سير العمل (GitHub Actions)

- `refresh-data.yml` — مجدول أسبوعيًا (وقابل للتشغيل يدويًا)، يجلب بيانات
  جديدة من Overpass ويفتح طلب سحب (Pull Request) بالتغييرات بدل أن يدفعها
  مباشرة، لمراجعتها قبل الدمج.
- `deploy.yml` — يُشغَّل عند كل push، يُنفّذ الاختبارات، يبني الموقع من
  البيانات المُلتَزَمة (committed)، ثم ينشر على Cloudflare Workers إن
  كانت أسرار `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` مضبوطة.

اضبط المتغير `SITE_URL` (GitHub Actions variable) على رابط النطاق
النهائي قبل أول نشر إن اختلف عن الرابط الافتراضي في `src/lib/config.mjs`.
