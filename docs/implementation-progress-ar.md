### ما تم التحقق منه

- بوابة الخرائط الحضرية التابعة لبلدي تعرض بيانات جيومكانية للمدن والطرق والخدمات، لكنها خدمة خرائط تفاعلية؛ لم أعثر في الصفحة العامة التي راجعتها على ملف حدود أحياء قابل للتنزيل مع رخصة إعادة نشر تجارية صريحة.
  - https://momah.gov.sa/ar/e-services/urban-maps
  - https://balady.gov.sa/ar/node/11430
- البوابة المكانية لأمانة منطقة الرياض تتيح البحث والاستعلام عن المحافظات والأحياء والشوارع، وتشرح بعض إمكانات تصدير ملفات Shape File؛ هذا لا يثبت وحده أن طبقة حدود الأحياء متاحة للتصدير أو أن استخدامها التجاري وإعادة توزيعها مسموحان.
  - https://www.alriyadh.gov.sa/ar/gis-portal
- أمانة الرياض تنص على أن رخصة البيانات المفتوحة تنطبق على مجموعات البيانات المنشورة على بوابتها المفتوحة، وتسمح بالمشاركة والإنشاء والتكييف مع الإسناد والحفاظ على إشعارات الترخيص. يجب فحص ترخيص كل مجموعة وملفاتها، لا افتراض أن كل طبقة في البوابة المكانية مفتوحة.
  - https://www.alriyadh.gov.sa/ar/open-data
- صفحة «جودة الحياة في الأحياء» في كتالوج الأمانة لم تعرض بيانات أو مرفقات عند المراجعة؛ لذلك لم نعتمدها مصدرًا لحدود الأحياء.
  - https://www.alriyadh.gov.sa/en/data-sets/quality-of-life-in-neighborhoods
- شروط استخدام المنصة الجيومكانية الوطنية تمنع نسخ المحتوى أو توزيعه أو إنشاء أعمال مشتقة أو استخدامه تجاريًا دون موافقة كتابية مسبقة، ما لم ينص ترخيص مستقل على خلاف ذلك. كما تعرض الهيئة مسارًا رسميًا لطلبات المنتجات والتراخيص الجيومكانية.
  - https://www.geoportal.sa/Geoportal/TermsOfUse
  - https://geosa.gov.sa/ar/Pages/GEOSAServicesPortal.aspx
- طلب البيانات المفتوحة لدى أمانة الرياض يقبل طلب مجموعة بيانات جديدة، وتذكر الأمانة أن الرد على الطلب خلال 30 يوم عمل.
  - https://www.alriyadh.gov.sa/ar/open-data-request
- وزارة البلديات والإسكان لديها نموذج مستقل لطلب البيانات المفتوحة.
  - https://momah.gov.sa/ar/request-open-data

### القرار الفني والقانوني

- لا نسحب أو ننسخ طبقات ArcGIS أو خرائط بلدي/المنصة الجيومكانية إلى مستودع الموقع قبل التحقق من مالك الطبقة والترخيص المكتوب وحق إعادة الاستخدام التجاري والتوزيع والأعمال المشتقة.
- يبقى OpenStreetMap المصدر الحالي المسموح به وفق ODbL مع الإسناد المطلوب.
- يستخرج النظام اسم الحي من وسوم OSM الصريحة فقط: `addr:neighbourhood`, `addr:suburb`, `addr:district`, `addr:city_district`. لا نستنتج الحي من الشارع أو الإحداثيات أو الاسم الحر.
- لا تنشأ صفحة حي إلا بعد استيفاء حد الجودة القائم: 8 أماكن على الأقل موزعة على تصنيفين على الأقل.
- لا نضيف حدودًا مرسومة يدويًا أو تقريبية كما لو كانت حدودًا بلدية رسمية.

### الطلب المطلوب من الجهات

طلب طبقة حدود الأحياء الرسمية للمدن والمحافظات، ويفضل بصيغ GeoJSON أو GeoPackage أو Shapefile، وتتضمن معرفًا ثابتًا لكل حي والاسم العربي والمدينة/المحافظة والبلدية التابعة وتاريخ التحديث والجهة المالكة ومصدر الحدود. يجب أن يوضح الرد كتابةً هل يسمح الترخيص بالاستضافة على موقع تجاري وإعادة عرض الحدود وتوزيع البيانات المشتقة، وشروط الإسناد والتحديث وأي مقابل مالي. يبدأ الاختبار بمدينة الرياض عند الحاجة، ثم يطلب نطاق وطني من وزارة البلديات والإسكان أو الهيئة المختصة.

**لا يبدأ الاستيراد البرمجي قبل استلام ملفات فعلية وموافقة استخدام واضحة.**

## المرحلة التالية — مضلعات الأحياء من OpenStreetMap

**الحالة البرمجية: مدمجة في main عبر PR #52؛ جلب ملفات المضلعات الفعلية لم يُتحقق من اكتماله بعد.**

- تُرفض نقاط `place=*` المركزية؛ فهي تسمي مكانًا ولا تحدد مساحته. ولا تُقبل علاقة بلا `boundary=place` أو مساحة غير مغلقة.
- تُحوّل حدود OSM إلى حلقات خارجية وداخلية؛ ويُستبعد المكان الواقع في ثقب داخلي، وتُفضّل حدود `neighbourhood` على `quarter` ثم `suburb` عند تداخل المساحات.

- الأمر المحلي: `npm run neighbourhoods:data`، والتحقق: `npm run validate:neighbourhoods`، والتقرير: `npm run audit:neighbourhoods`.
- مصدر المضلعات هو OpenStreetMap المجتمعي وفق ODbL والإسناد المطلوب. لا توصف هذه المضايعات بأنها حدود رسمية للأمانة، وتظل طبقة الحدود الرسمية طلبًا منفصلًا.

**التحقق:** PR #52 مدمج بعد نجاح الاختبارات، والتحقق من المضلعات، وتصدير D1، وتقرير التغطية، وبناء الموقع. المتبقي هو فحص أول دفعة فعلية (الرياض وجدة ومكة والدمام والخبر) وعدد المضلعات وجودتها قبل دمج أي ملفات بيانات. لا نُنشئ صفحات حي من أسماء بلا مضلعات أو من نقاط مركزية.


## سياسة عدم تحميل Cloudflare أي تكلفة — 24 نوفمبر 2026

**القيد المعتمد: لا تُضاف أي خدمة أو مورد Cloudflare مدفوع، ولا يُفعّل ترقية تلقائية أو تشغيل مدفوع.**

- ملفات الأحياء تُجلب وتُراجع وتُختبر عبر GitHub Actions وOverpass API؛ هذه العملية لا تنشئ قاعدة D1 أو KV أو R2 أو Queue أو Durable Object على Cloudflare ولا تنشر Worker.
- تم إيقاف Cloudflare Previews لهذا الـWorker، وتغيير `production_settings.path_includes` إلى `__manual_cloudflare_deploy_only__`؛ لذلك لا تُطلق تغييرات ملفات المشروع المعتادة بناءً أو نشرًا تلقائيًا. يجب تشغيل النشر يدويًا وبعد طلب صريح فقط.
- تبقى `auto_build_enabled` مفعلة على مستوى تكوين Workers Builds، لكن فلتر المسار لا يطابق ملفات المشروع العادية، و`previews_enabled=false`. لا يُعاد توسيع الفلتر أو تفعيل Previews دون مراجعة شرط التكلفة أولًا.
- آخر نسخة إنتاجية قبل إيقاف التشغيل التلقائي: Worker version 63 بنسبة 100%. تعديل إعدادات Builds لم يرفع نسخة Worker جديدة.
- يعرض سجل Builds المتاح 95 عملية، منها 90 مكتملة بإجمالي وقت تنفيذ مسجل يقارب 34.8 دقيقة؛ وتقرير Cloudflare الحالي يقول إن حد دقائق البناء لم يُستنفد. توضح وثائق Cloudflare أن الخطة المجانية تتضمن 3,000 دقيقة بناء شهريًا، وأن الملفات الثابتة لا تفرض رسوم طلبات أو تخزين ضمن Workers Static Assets.
- صفحات الملفات الثابتة تُخدم من Workers Static Assets (طلبات وتخزين مجانيان بحسب الوثائق). أما الوظائف التي ينفذها Worker، مثل `/seo` وواجهات `/api/seo/*` وصفحات تفاصيل الأماكن ومواقيت الصلاة، فتقع ضمن حد Workers Free البالغ 100,000 طلب يوميًا و10 ms CPU لكل استدعاء؛ بعد تجاوز الحد في الخطة المجانية تُرفض الاستدعاءات بدل احتساب طلبات إضافية مدفوعة. لا نرفع الحساب إلى Workers Paid.
- صلاحية قراءة الفواتير والاشتراكات غير متاحة في اتصال Cloudflare الحالي؛ لذلك لا يُدّعى التحقق من فئة الاشتراك أو الرصيد المالي الفعلي. لا نغيّر خطة الحساب أو وسيلة الدفع أو إعدادات الفوترة.
- لا تُنشأ موارد Cloudflare جديدة لهذا المشروع دون موافقة صريحة. فشل بلوغ الحصة المجانية يجب أن يوقف الميزة أو يعرض خطأً بدل الانتقال تلقائيًا إلى خطة مدفوعة.

**طريقة النشر المعتمدة مستقبلًا:** تعديل ومراجعة واختبار على GitHub أولًا؛ ثم نشر Cloudflare يدويًا فقط عند طلب المالك، وبعد التأكد أن مسار النشر لا يفعّل خدمة مدفوعة. لا نستخدم Cloudflare Workers Builds للنشر التلقائي حاليًا.


## توضيح تنفيذي ملزم لسياسة صفر تكلفة Cloudflare — 24 نوفمبر 2026

- تُقدَّم سياسة صفر تكلفة Cloudflare على أي بند قديم في خارطة المشروع أو PR سابق. البنود الموسومة «موقوف» أعلاه ليست موافقات تنتظر التنفيذ؛ بل حظر إلى أن يطلب المالك تغيير القرار صراحة.
- يبقى D1 مجرد كود محلي ومولّد SQL واختبارات. لا قاعدة بعيدة، ولا binding، ولا Migration عن بعد، ولا استيراد إلى Cloudflare.
